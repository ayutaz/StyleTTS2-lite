## 4. 判定ゲート（PoC後の進路判断）

### Gate A: 品質
- MOS / 誤読率 / 自然さが目標水準に達しているか

### Gate B: 性能
- RTF < 1.0 を満たすか
- 初回発話レイテンシが許容範囲か

### Gate C: 運用性
- モデルサイズ/RAM使用量が端末要件に合うか
- Sentisの演算子制約に収まっているか

#### 判定結果の例
1. **StyleTTS2‑lite 継続改良**（最有力）
2. **ハイブリッド化**（liteにPLBERT/一部表現を追加）
3. **StyleTTS2フル移行**（品質要求が高くPoCでは足りない場合）

## 5. リスク管理

- 演算子未対応: 分割/置換で回避、必要ならONNX Runtimeを検討
- G2Pライセンス: GPL/AGPL回避の徹底
- 学習コスト: 小規模検証 → 段階的スケール
- 日英統合の品質低下: 言語別データ/トークン戦略を採用
